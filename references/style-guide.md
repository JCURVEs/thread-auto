## 말투

### 기본 어미
- "요"체: 해요, 이에요, 하는데요, 거든요
- 질문형 자주 사용
- 겸손한 표현

### 금지 표현 ❌
- "혁신적인", "획기적인", "놀라운"
- "정말", "매우", "엄청"
- "~할 수 있습니다", "~하게 됩니다"
- "이것은 ~입니다"

### 권장 표현 ✅
- "~해요", "~인데요", "~거든요"
- "쉽게 말하면", "예를 들면"
- "제 생각엔요"
- 구체적 숫자, 실제 사례

### 리듬
- 짧은 단정문을 섞는다: "핵심은 이겁니다.", "먼저 용어부터."
- 겉보기와 실제를 대비한다: "겉보기엔 ...", "근데 뜯어보면 ..."
- 문제를 현장 언어로 판정한다: "이러면 실무에서 쓰기 어렵습니다."
- 전문용어는 바로 풀어쓴다: "기술명(쉬운 설명)"처럼 괄호 설명을 붙인다.
- 문장은 길게 늘이지 않고 한 줄에 한 판단만 담는다.

## 구조

### 멀티스레드 포맷
1. 제목: 한 줄로 핵심을 직관적으로 전달
2. 후킹: 5줄 구성
   - 발표 주체와 내용을 명시
   - 왜 중요한지 호기심 유발
   - 마지막 줄은 고정 문구 사용
3. 본문: 1/부터 7/까지 논리적으로 전개
   - 각 슬라이드는 소제목으로 시작
   - 각 슬라이드는 7-9줄
   - 전문용어 옆에는 쉬운 설명 병기

### 논리 전개 순서
1. 기존 상식 뒤집기
2. 근본적 문제/병목
3. 핵심 접근법/역발상
4. 구체적 기술 구현
5. 기술 깊이
6. 결과/성과
7. 미래 전망/임팩트

### 후킹 패턴
1. 발표 주체와 핵심 발표를 첫 줄에 명시
2. 겉보기와 실제 의미의 차이로 호기심 유발
3. "근데 뜯어보면"으로 병목이나 실무 문제를 드러냄
4. 마지막 줄은 "핵심내용 정리했습니다🧵"

### 본문 패턴
1. 소제목은 구조명이 아니라 해당 기술/문제/결과를 담는다.
2. 초반에는 용어를 짧게 정의한다.
3. 중반에는 "왜 어려웠는지"와 "어떻게 풀었는지"를 분리한다.
4. 후반에는 숫자, 참여 기업, 산업 적용처로 실용성을 증명한다.
5. 마지막은 기술 설명이 아니라 산업 변화의 여운으로 닫는다.
